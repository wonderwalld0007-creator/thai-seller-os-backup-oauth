Privacy Policy

Application: Thai Seller OS Backup · Effective date: 13 October 2026

1. Purpose and operator

Thai Seller OS Backup is a personal-use utility operated by the owner of the Google account that authorizes it. Its purpose is to back up selected local files in encrypted form, verify backup integrity, and recover files when needed. It is not offered as a public service.

2. Google data and permissions

  • https://www.googleapis.com/auth/drive.readonly permits viewing and downloading existing Drive files and their metadata. This permission is account-wide; the utility is configured to operate on a selected backup destination, not to browse unrelated files for other purposes.
  • https://www.googleapis.com/auth/drive.file permits creating files and managing files created by, or explicitly made available to, this application. It is not unrestricted write access to all existing Drive files.

File metadata such as identifiers, names, sizes, dates, and available checksums is used to locate and verify backup objects. Existing encrypted backup content may be downloaded for integrity checks or recovery. Account information supplied by the Drive API may be used to verify that the intended account is connected.

The permission request alone does not enable scheduled backups or approve an upload. Writes are limited by the owner's separately approved backup workflow. The application does not request Google account passwords.

3. Use and sharing

Google user data is used for the owner's backup, integrity verification, and recovery activities. It is not sold, used for advertising, or used to develop, improve, or train generalized AI or machine-learning models.

Google processes the data needed to provide Drive storage and OAuth. GitHub hosts these public informational pages. Backup data and OAuth credentials are not published to this website or its public repository. The owner's use remains subject to the applicable provider terms and privacy policies.

4. Encryption and local storage

Backup content is encrypted locally with restic before upload. Google Drive stores the encrypted backup objects and associated cloud metadata. Local source files, restored files, backup manifests, and verification records remain on the owner's computer unless included in a separately approved encrypted backup scope.

OAuth credentials are stored in locally access-restricted configuration files so that approved tasks can authenticate without a browser session. The recovery password is kept separately from cloud backup uploads. These measures do not guarantee protection against compromise of the owner's computer, account, or recovery password.

5. Retention and deletion

Encrypted backup snapshots are retained until the owner approves their removal. No automatic cloud snapshot deletion or pruning is currently enabled. Local authentication configuration and verification records are retained while needed for the owner's backup operation and troubleshooting.

Revoking authorization does not delete existing backup files or erase local copies. Their retention or deletion is a separate action controlled by the owner.

6. Revoke authorization

The owner can review and remove this application's access through Google Account third-party connections. Revocation prevents future access using that authorization. The owner should also stop any separately configured tasks and remove no-longer-needed local authentication configuration. Existing encrypted backups still require the recovery password to restore.

7. This website

These pages have no forms, embedded sign-in, advertising, analytics scripts, or application-set cookies. GitHub may process ordinary request information, such as IP addresses, as the hosting provider; see the GitHub Privacy Statement. Google services have their own Privacy Policy.

8. Contact and changes

The account owner is also the application operator. The support contact is provided on the application's Google OAuth consent screen. This policy will be updated if the application's purpose or data practices change.
